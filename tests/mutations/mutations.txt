4. Dead !addr.IsRelayable() guard in RelayAddress (2288)                                                                                                                              
                                                                                                                                                                                        
  if (!fReachable && !addr.IsRelayable()) return;
  The only caller (5695) pre-gates on addr.IsRoutable(), and IsRoutable() ⊆ IsRelayable(), so !addr.IsRelayable() is always false here. Unreachable from production. High confidence 
  it's dead (defensive, but worth noting/documenting).                                       
   
  5. First self-announcement isn't added to m_addr_known (5413-5420)

  The initial self-announcement is sent directly via MakeAndPushMessage and skips PushAddress/m_addr_known:
  if (IsAddrCompatible(peer, local_addr)) {                                                  
      std::vector<CAddress> self_announcement{local_addr};
      MakeAndPushMessage(... self_announcement ...);   // not marked known
  }                                            
  …whereas every later self-announcement goes through PushAddress (5423), which records it in m_addr_known. Net effect: right after the first announcement, our own address isn't in the
  known-filter, so it can be redundantly re-sent (via relay or the next flush). Low impact (the bloom filter resets daily anyway), but an asymmetry. Medium confidence it's unintended.
